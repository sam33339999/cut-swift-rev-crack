## 看到的現象

只掛 LoRA 評 `e01`（17 乘 23）。模型先寫出 `17 × 23 = 391`，接著一直重複詞片段 `ANS`，直到 `max_tokens` 8192 被截斷。可見回答是空的，沒有 `ANSWER:` 那一行，算錯。`e02` 的四個 seed 也一樣。

這不是思考變長。思考在答案出現後就停了，剩下的 token 是 `ANSWER` 的碎片迴圈。

## 訓練實際做了什麼

- 32 題，都是 `make_problems.py` 的整數數學，和開發集同一類、不同數字。每題 4 條，seed 201–204，共 128 條，124 條答對。
- 答錯獎勵是 0。答對的整條序列一起加分，包含結尾的 `ANSWER:`。
- LoRA rank 8，學習率 `1e-4`，兩輪更新，KL 係數 0.01，沒有梯度裁剪。
- `train_stats.json`：178 次更新，78 條因為超過 4096 token 或顯存不夠而跳過。跳過的是比較長的那批，也就是複查懲罰該壓下去的樣本。
- 評分時訓練和 vLLM 曾擠在同一個行程，顯存不足。後來改成訓練用子行程。這只解決開服務，沒有解決迴圈。

## 為什麼離開原目標

原目標是少想幾步，而且還答對。這次最佳化的是「在這批數學題上把 `ANSWER` 的機率拉高」。題型窄，每條正確樣本都以同一個答案格式結尾，更新又沒有把優勢限制在 `<think>` 裡，所以權重記成了答題儀式，不是提早寫出 `</think>`。

## 若再做第 45 條，要守住的事

獎勵公式可以留著：答錯是 0，答對才給整體長度分，並扣第一次答對之後的思考比例。調整的是更新落在哪裡。

- 優勢只加在 `<think>` 裡的 token，以及把 `</think>` 寫出來的那個 token。`ANSWER:` 那幾個 token 維持原模型的機率，不再越推越響。
- 長樣本要留下。超過長度就只對「第一次答對之後」那段做反向傳播，不把整條丟掉。
- 學習率用 `1e-5`，只更新一輪，梯度裁到 1.0，KL 係數 0.1。
- 開發集 56 筆之前，先用 `e01` 抽 1 條。前 200 個 token 若重複 `ANS`，這個 adapter 作廢，不開整輪評分。
- 通過的定義仍是難題思考中位數至少少 15%，答對少不超過 1，而且軌跡仍是計算過程，不是重複詞。
